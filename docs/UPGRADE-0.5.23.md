# 0.5.23 归档兼容与错误显示修复

DSH 升级或恢复旧会话后，持久化读取会补充格式版本、缺失的 Agent 预设信息。旧插件把整个会话头作为不可变身份比较，因此可能拒绝继续归档，页面只显示一条泛化错误。

本版把编码版本与会话来源分开，只允许补齐原先缺失的预设信息。会话编号、创建时间、工作目录、父会话和代理来源仍须一致；已确定的预设发生冲突、旧事件内容改变或事件序号缺失，继续拒绝覆盖。

后台归档和摘要失败分别提供固定、脱敏的原因。两页均可查看后台错误，接管状态提醒仍只在开启接管时显示。只有对应工作成功后清除旧错误；用户更新设置造成的取消不新报失败，也不抹掉尚未恢复的旧错误。

## 更新

使用 DSH 自带插件管理更新，或运行：

```sh
dsh plugin --profile web add ./SuperLcm-0.5.23.tgz
```

原文数据库、摘要、模型选择和压缩参数继续保留。其它使用 SuperLcm 的 profile 应更新至同版。无需额外 Web 后台。

## 验证

50 项现行测试通过，包含旧会话头补齐、真实来源与原文冲突拒绝、重试取消、错误恢复和界面显示。两条真实历史会话的隔离回放完整补齐 1,537 条事件，并验证旧事件内容未变。macOS 官方安装升级流程从 0.5.21 到本版通过，中文与特殊字符目录、配置、摘要和模型目录保留。

Windows、Linux 本轮没有实机执行；GitHub Actions 按用户要求保持关闭。真实模型生成质量与供应商可用性不由这些本地测试证明。

## 无法由宿主升级的极旧日志

实际历史导入另发现一条 v0 日志，由 DSH 自身以 `SessionFormatUnsupportedError` 拒绝迁移：结束事件跨过了未关闭的压缩事件。这类历史会话显示 `LEGACY_FORMAT`，该会话暂未归档，原文件保持不变。插件不会伪造结束事件或改写原文来强行通过宿主检查；此提示与摘要模型认证失败分开。
