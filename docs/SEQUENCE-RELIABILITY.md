# 连续使用与失败恢复验证

发布入口仍是 `npm run verify:release`。新增用真实 DSH SDK 执行的连续运行测试，两版的 DSH 接管侧运行同一组场景。所有模型响应均在本机生成，测试不会调用供应商 API 或执行用户任务。

## 每次发布重复验证

- 64K、100K 和 1M 三种上下文窗口，各执行 64 次真实 `Agent.send`。至少完成多次独立压缩，活动输入保持在允许范围内，重新组装前的旧请求不送到模型适配器。
- 每轮核对已经写入的原始事件摘要哈希，保护最新真实用户输入，检查提交次数和唯一压缩身份。结束后从原始会话重建摘要树，检查来源和子节点完整性。
- 摘要传输失败、输出截断时，拒绝未完成摘要并限制重试；到期后的真实新输入能重新准备并继续，满上下文的请求在适配器前被拦截。
- 关闭宿主后，从相同原始事件和数据库重新建立 DSH 会话，恢复已完成草稿并一次提交，无需再买摘要。
- 策略变更取消的迟到输出不能重新提交；切换主模型容量时旧草稿失效，新策略重新计算范围和容量。
- 临时草稿保存失败后保留已完成前缀，下一次合法请求可以恢复。
- 等待摘要期间停止真实请求，再发送继续。停止的输入仍在，迟到摘要只作为草稿，下一请求重新组装成功。

## 检查范围

这些测试锁定流程完整性和确定性失败恢复。模型是否准确理解用户意图仍需真实任务质量评估；用合成摘要通过流程测试不能证明语义质量。运行范围是当前 DSH SDK 的 macOS 宿主；Windows 和 Linux 实机结果另记，GitHub 自动测试保持关闭。

新增问题应先做最小复现，再将复现保留为永久回归，两版同步修复。已有发布入口会执行本页的连续运行测试，避免只验安装成功和单轮正常响应。
