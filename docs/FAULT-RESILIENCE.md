# 摘要失败与最后一次压缩

独立 DSH 版 0.5.32 与完整 SuperLcm 0.5.29 共享这次 DSH 修复。默认仍仅归档与后台摘要；下面的上下文替换行为仅在用户启用 SuperLcm 接管压缩时生效。

## 恢复行为

每次模型调用有自己的截止时间。主摘要路线超时可尝试已配置的备用路线，备用使用新的时限。服务即使忽略取消，插件也会结束等待并拒绝迟到结果。语言或标题不合格的修正次数仍有限，不会无限重试。

用户停止当前请求时，关联的后台压缩被取消，准备草稿被丢弃；迟到正文不能写入或替换。切换设置及关闭服务也会撤销旧工作的写入资格。

鉴权失效与额度耗尽使用较长冷却，避免同一轮不断购买失败请求。真实宿主的账户额度、未登录、登录令牌失效及缺失/无效凭证均转换为固定安全类别，供应商原文不会进入诊断。

已经生成的摘要在临时写入失败后保留。下一次正式请求复用它，不重新购买整段摘要。若上下文替换已成功而结束记录未写入，依据原始开始、摘要、检查点与精确来源证明补结束；重启后也可恢复，禁止再次替换相同范围。诊断会标出尚未闭合的操作。

## 对话模型最后兜底

只有到达紧急门槛，并且所有已配置摘要路线明确发生额度耗尽或鉴权不可用且仍处于冷却，才尝试当前对话模型。普通限流、临时连接故障、摘要质量问题不会触发这一层。

优先提交已有摘要；若仍不足以腾出空间，取一次固定的完整可压前缀，用经过精确来源验证的现成摘要加尚未摘要的原文交给当前对话模型。最近原文、工具配对边界和当前用户输入仍受保护。这里仅调用对话模型一次，不再次调用摘要备用，也不进行质量修正循环。

成功结果经过完整结束、语言、标题、收缩及来源检查，保存为可恢复草稿后才替换。临时提交故障仍复用这份结果。对话模型也失败或超时就保留当前请求并明确失败；用户停止后的迟到结果不能写入。此次最终调用可能让主请求等待，不能保证零等待。

## 后台摘要与验证范围

后台仅归档的模式使用相同的完整结束与取消防护。完整 SuperLcm 的 API 请求与响应体也受截止限制，HTTP 429 中的额度耗尽与短暂限流分别记录。后台摘要不会改写宿主上下文。

永久回归通过真实安装的 DSH SDK、纯离线适配器、合成原文、临时 SQLite 和正式 Agent.send 运行，覆盖超时、忽略取消、备用耗尽、最终主模型兜底、临时写失败、持久结束失败、重启恢复、原文哈希、当前输入和重建树。完整版本另覆盖 API 取消及额度诊断。两版核心和相关生命周期测试有配对检查。

离线故障注入证明已测路径的恢复与数据一致性。它不验证真实模型摘要的语义质量、全部供应商或 Windows/Linux 实机；GitHub Actions 保持关闭。永久不可写的磁盘不能被重试修复，插件保留明确失败。
