# 连续使用与故障恢复测试台

在源码仓库执行以下命令。两版使用同一套测试和压缩修复。独立版命令与完整版相同：

```sh
npm run test:reliability
npm run verify:release
```

须先安装项目开发依赖或提供已安装的 DSH 宿主。测试加载器优先使用仓库的宿主依赖；可通过 `SUPERLCM_DSH_RUNTIME` 指定宿主的 `package.json`。产品不依赖测试机器的固定路径。

测试使用临时目录、真实已安装 DSH SDK 和离线模型响应，不改真实对话、生产配置或模型，不调用付费接口。GitHub Actions 保持关闭。

## 覆盖内容

- 64K、200K、500K、1M 模型窗口，每种窗口分别连续发送 72 轮；后台延迟期间继续发送，验证多次压缩和请求重组。
- 真正的三路并行工具，连续七轮产生大输出；单次大工具输出跃过压缩门槛。
- 摘要主路线超时、忽略取消、额度耗尽、凭证失败、限流、网络失败、流缺结束及质量拒绝；备用和最终对话模型的有界恢复。
- 当前输入保护、固定系统提示、通过正式请求接口切换窗口，以及供应商用量校准后的压力和输出预算。
- start、summary、replace、end 和草稿保存失败；已完成结果不重购、取消后的晚结果不提交、重复检查不重复替换。
- 正式 JSONL 持久化，退出一个 Node 进程后在另一个进程调用 `ctx.agents.resume`。覆盖自然 ready、已替换但结束持续失败、只有 start，以及 summary 后未替换和取消后的中断。内存 seed 测试单独保留，不作为真实重启证据。
- 每轮核对原始事件哈希、当前输入、工具完整边界和全新数据库重建；压缩完成后反复检查不得新增替换。

每次提交在首次生命周期事件前，先独立持久化收尾归属记录。取消可以让摘要草稿失效，但不会抹掉这份归属，重启时仍须补失败结束记录。取消使未提交的草稿失效后，后续明确请求可能重新生成摘要；仍有效的未取消稿和已提交稿不重复购买。

若结束记录仍无法写入，保留合法的未完成尾部，阻止下一轮跨过它。恢复时只通过取得所有权的写句柄追加结束记录，再由宿主补轮次结束；不在只读访问时修改归档。已完成替换只补结束，未完成替换标记失败并复用仍有效的摘要草稿。

## 验证边界

离线响应验证流程和故障处理，不证明真实模型摘要足够忠实或后续回答质量。窗口预算依赖宿主的附件价格和已有供应商用量校准，首次未知文本密度不是精确分词保证。单条不可压缩的新输入过大时明确拒绝并保留请求。

本次修复防止以后产生非法跨轮日志。旧版本已经写入非法顺序的归档，需要另行备份和专门恢复，不能靠尾部补一条记录修复，也不能把它报成可直接恢复。

本机验证不能代替真实 Windows、Linux 运行验证；没有启用云端自动测试。每次发布须保存实际测试结果，不以本文件描述代替通过回执。

本轮发布结果：独立版 0.5.35 的 222 项、完整版 0.5.33 的 432 项基础与 181 项 DSH 运行时测试通过；其中可靠性矩阵两版各 53 项。独立复核两版各 29 个额外场景通过，包括 72 轮真实并行工具对话和 70 次替换。上述结果来自隔离 macOS 宿主与离线模型，不将模型语义品质或其它平台列为已验证。
