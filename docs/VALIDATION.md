## 0.5.22 升级与路径审查

独立审查发现自定义数据库文件名会被压缩组件替换为 `lcm.sqlite`，从而出现两份数据库；修复后所有运行组件使用同一确切路径，旧 `archiveHome` 目录配置继续兼容。真实 DSH 运行时回归验证接管开启与关闭，数据仍在自定义文件里。43 项现行测试通过。

`npm run test:install` 从仓库中读取已发布 0.5.21 的文件，打包后使用官方 `dsh plugin` 安装，在包含中文、空格、`#` 和 `%` 的隔离目录启动实际宿主。保存自定义参数和旧摘要后，正式更新到 0.5.22 并重新启动，验证设置、旧摘要、模型目录保留且继续使用原生压缩。测试通过，不需要手工链接依赖。

GitHub 工作流已配置 Windows、Linux 和 macOS 上的同一真实安装升级测试。本机核实仓库 Actions 开关为关闭，当前结果不能沿用 9 月旧提交的 Windows 成功记录。用户于 2026-10-08 明确选择保持关闭，只出审查报告；本轮未执行 Windows、Linux 远端测试，也不再等待启用确认。

旧版分库恢复只处理所选数据库已经记录的会话，复制缺失的压缩节点和准备草稿，并保留摘要拒绝记录。原文件保持只读。已有已提交或已丢弃的草稿不会重新激活。来源损坏时报警并继续启动原生压缩保护；多宿主同时写入时，恢复不能覆盖新内容。
